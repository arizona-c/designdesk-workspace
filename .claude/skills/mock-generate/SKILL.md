モックアップを Figma に描く。材料は3つ: 作業者の指示文、ワイヤー生成で決めた画面（あれば優先）、既存の参考デザイン。描いたら人がレビューし、その結果が知識に戻る（/mock-review）。

## 手順

1. `mock_get_knowledge` を読む。**adopted（採用済み）は全文を守る**。汎用的なデザイン常識より採用済みの知識を優先する。採用済みがゼロなら、その旨を伝えたうえで参考デザインだけを頼りに描く（精度が低いことを断る）。
2. `mock_component_catalog` を読む。流用できる部品がある箇所は **ほぼ必ずインスタンス**で置く（`figma.importComponentByKeyAsync(key)` → `createInstance()`、バリアントは `setProperties`）。部品が無い箇所だけ形と文字で描く。
3. 対象の画面がワイヤー生成にあれば（wire_screens）、その区画の並びを土台にする。参考にする既存画面があれば `mock_get_samples` で構造（区画・余白・文字・色）を読む。
4. 作業者に確認する: 描く画面の一覧、出力先（既定は同じファイルの新しいページ「Mock yyyy-mm-dd 画面名」。指示があればそれに従う）、使う主な部品。**同意を得てから描く**。
5. Figma MCP（`use_figma`。先に /figma-use を読む）で新しいページを作り、そこにだけ描く。**既存のページ・ノードには一切触れない**。画面は1画面1 Frame、名前は画面名。
6. 描き終えたら:
   - `create_ticket` でレビュー用チケットを起票する。タイトルは「モック: 画面名（レビュー依頼）」、説明にはページ名・材料にした知識の見出し・迷った点。担当は自分、レビュアーは作業者に確認。Frame の URL を紐づける
   - `mock_record_run`（kind: "generate"・page_name・brief・ticket_seq・count）で記録する
   - 作業者に「レビューで直すべき点が出たら /mock-review で知識に戻せます」と案内する

## してはいけないこと

- 既存のページやノードを変更・削除しない（描くのは新しいページの中だけ）
- 部品が流用できる箇所を形で描かない（インスタンスを使う）
- 採用されていない候補を材料にしない
- 確認なしに大量に描かない（画面数と出力先を先に示す）
